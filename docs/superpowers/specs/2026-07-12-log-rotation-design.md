# Dever 日志按大小滚动设计

## 背景

Dever 当前通过 `dever/log/log.go` 长期开启 `access.log` 和 `error.log`，文件只追加、不滚动。当前开发环境的 `access.log` 已增长到约 70MB，继续运行会让单个日志文件持续膨胀，增加磁盘占用和排查成本。

## 目标

- 文件日志达到 10MB 后自动备份当前文件并创建同名新文件。
- `access.log` 和 `error.log` 独立滚动。
- 每个日志最多保留最近 5 份备份，自动删除更旧的同源备份。
- 现有项目不修改配置也能获得默认滚动行为。
- 不改变 stdout、stderr、off 等非文件输出行为。

## 非目标

- 不增加按日期滚动。
- 不压缩备份。
- 不接入操作系统 `logrotate`。
- 不为多进程同时写同一个日志文件提供跨进程锁。

## 方案

### 配置

在 `config.Log` 增加两个全局字段：

- `maxSizeMB`：单个活动日志文件的大小上限，默认 10。
- `maxBackups`：每个日志文件保留的备份数，默认 5。

`App.applyDefaults` 负责给配置文件加载路径补默认值。日志包同时使用框架公开的默认常量处理直接构造 `config.Log` 的调用，避免未经过配置加载时出现不一致。

当前需求对访问日志和错误日志采用相同策略，因此不在 `LogTarget` 内重复定义滚动字段。后续只有出现真实的独立策略需求时，才扩展目标级覆盖。

### 滚动 Writer

在 `dever/log` 内增加一个职责单一的文件 Writer，封装以下行为：

1. 以追加模式打开活动日志文件，并记录当前大小。
2. 每次写入前判断“当前大小 + 本次内容”是否超过配置上限。
3. 超过上限时关闭活动文件，将其重命名为带 UTC 时间戳的备份文件，再创建同名活动文件。
4. 滚动完成后扫描同目录、同基础文件名且符合框架备份命名规则的文件，按名称排序并删除最旧文件，直至只剩 5 份。
5. 使用互斥锁保护打开、写入、滚动和关闭，保证单进程内并发安全。

备份文件保留原扩展名，命名示例：

```text
access-20260712T105230.123456789Z.log
error-20260712T105231.123456789Z.log
```

时间戳包含纳秒并使用 UTC，既降低同一秒内重名风险，也让文件名的字典序与生成顺序一致。

`resolveWriter` 的文件分支改为创建该 Writer；访问日志和错误日志继续复用同一条解析和装配流程，不新增平行配置路径。

### 边界行为

- 如果活动文件启动时已经超过 10MB，则首次新写入前立即滚动。
- 单条日志本身超过 10MB 时，空文件先接收该条日志，避免产生无意义的空备份；下一次写入前再滚动。
- 只删除当前日志文件按规定命名生成的备份，不影响目录里的其他文件。
- `Configure` 重新配置日志时，继续先构造新 Writer，再在锁内替换并关闭旧 Writer。

### 错误处理

- 目录创建或首次打开失败时，沿用现有行为：访问日志回退 stdout，错误日志回退 stderr。
- 滚动过程中关闭、重命名或新建失败时，尽力恢复活动文件并继续写入；无法恢复时向调用方返回错误。
- 清理旧备份失败不阻断当前日志写入，避免磁盘清理问题扩大为日志丢失。

## 修改范围

- `dever/config/config.go`：新增配置字段和默认值。
- `dever/log/log.go`：文件输出接入滚动 Writer。
- `dever/log/rotate.go`：集中实现文件滚动和备份清理。
- `dever/README.md`：更新日志配置示例和行为说明。

不修改业务 module、package、生成文件或前端代码。

## 验证

遵守项目要求，不运行 `go test`、其他测试命令、`npm run build` 或任何 build。实现后只进行以下静态核对：

- 使用 `gofmt` 格式化改动的 Go 文件。
- 检查 Git diff，确认修改范围和配置字段一致。
- 运行 Dever skill 提供的静态 audit（如果该脚本支持本次框架文件）。
- 保留当前 CTF 服务供用户手动验证滚动结果。
